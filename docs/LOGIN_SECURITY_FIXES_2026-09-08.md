## 공격 시나리오, 수정, 회귀 검증

|---|---|---|
| Brute Force | 한 계정에 반복 추측. DB 원자적 계정·IP·네트워크·전역 제한 적용 | 병렬 요청에서도 허용 횟수 초과하지 않음 |

| 세션 탈취 | 탈취 세션으로 복구 수단 변경·장기 인증 확보. 민감 작업 비밀번호 재확인, 세션/장기 토큰 폐기 | 재설정 후 이전 세션/장기 토큰 거부, MFA 변경 후 다른 세션 폐기 |

| Remember Me | 로컬 저장 비밀번호 탈취. 비밀번호 저장 제거, OS 보호된 회전 토큰으로 대체 | 기존 저장 비밀번호 제거, 회전·재사용 탐지·만료 JWT 로그아웃 폐기 |
| 비밀번호 정책 | 짧거나 유출된 비밀번호, bcrypt 길이 예외. 신규 15~128자, 유출 검사, 길이 예외 처리 | 길이/반복 패턴/유출 거부, 긴 기존 입력에서 서버 오류 없음 |

MFA는 사용자가 등록하면 서버에서 강제된다. 모든 기존 사용자에게 강제 등록하는 정책은 포함하지 않는다. 탈취된 현재 유효 토큰의 사용 자체를 전부 막는다고 보장하지 않는다. 등록/아이디 확인 응답 변경은 stmaker 경로 중심이며 다른 제품 인증 전반을 감사한 것은 아니다.

## Cloudflare 없는 최종 구성

사용자 요청에 따라 Turnstile 위젯, Siteverify 호출, 공개 site-key API 및 CSP의 Cloudflare 허용 항목을 제거했다. 추가 Cloudflare 계정이나 키는 필요하지 않다. Vercel Functions와 기존 Supabase/Redis 공유 제한 저장소를 사용한다.

재설정 요청은 출발 IP 제한 → IP/계정 발송 제한 → 전체 발송 제한 → 암호화 큐 순서로 처리한다. 기본 600초 고정 창에서 출발 IP 10회, 계정 3회, 전체 120회까지 허용한다. 확인 요청은 IP당 30회다. 인스턴스가 여러 개여도 원자적 공유 카운터를 사용한다. 차단된 출발 IP는 후속 계정 한도를 소진하지 않으며, 어느 단계든 저장소 장애가 나면 발송하지 않고 503을 반환한다. 허용/제한된 발송 요청은 같은 202 메시지를 반환한다.

Fetch Metadata의 cross-site/same-site 요청도 거부한다. 이는 다른 사이트의 브라우저 악용을 줄이는 보조 수단이며, 비브라우저가 위조 가능한 헤더를 사람 인증으로 취급하지 않는다. CAPTCHA가 없으므로 저속 분산 자동화 자체를 식별하지 않는다. 전체 제한은 발송 남용을 제한하지만 공격자가 한도를 소진하면 정상 복구도 창이 바뀔 때까지 지연될 수 있다. 고정 창 경계에서는 인접한 두 창의 한도가 짧은 시간에 허용될 수 있다.

Vercel의 기존 `Password reset request observation` 규칙은 draft이며 초과 요청을 log하는 설정이다. 이를 실제 차단 중인 WAF로 주장하지 않는다. 현재 필수 차단은 애플리케이션의 공유 제한이 담당한다. 요금제 변경이나 방화벽 전체 차단은 하지 않았다.

## 운영 적용 순서

1. 실제 서버 NewshoppingShorts의 마이그레이션/새 테이블 및 기존 reset 환경 설정을 확인한다. 과거 project-user-dashboard 서버 복사본을 운영에 덮어쓰면 안 된다.
2. Vercel에 이미 설정한 `AUTH_MFA_ENCRYPTION_KEY`를 유지한다. 재생성하거나 로그/소스에 남기지 않는다.
3. 사이트의 기존 proxy 서명 secret과 공유 제한 저장소 설정을 유지한다. `/api/readiness`의 `passwordResetProtectionConfigured`는 해당 필수 설정을 확인하며 실제 저장소 연결 성공까지 보장하는 검사는 아니다.
4. 서버와 새 클라이언트/사이트를 조율하여 배포한다. 서버 우선 적용 시 구버전 stmaker 가입은 업데이트가 필요하고 기존 비밀번호 로그인은 호환된다.
5. 전용 테스트 계정으로 가입 → MFA 등록 → 로그인 → 자동 로그인 → 로그아웃 → 복구 메일 → 재설정 → 이전 토큰 거부를 확인한다. 사이트 및 서버 PR #8까지 운영 도메인 전환을 완료했다. 마지막 메일 헤더 수정은 배포 한도에 걸려 운영 적용과 실제 메일 검증이 남아 있다. 최신 상태와 재개 절차는 [운영 적용 기록](LOGIN_SECURITY_PRODUCTION_2026-09-08.md)을 따른다.

신규 비밀번호는 15~128자 및 HIBP 범위 조회 검증을 적용한다. 조회 장애는 fail-closed이며 HTTPS 외부 연결이 필요하다. MFA 등록 후 구버전 서버로 단순 롤백하면 보호가 사라지므로 키와 새 테이블을 보존한다. MFA는 등록한 사용자에게 강제되며 전체 기존 사용자 강제 등록 정책은 포함하지 않는다.
