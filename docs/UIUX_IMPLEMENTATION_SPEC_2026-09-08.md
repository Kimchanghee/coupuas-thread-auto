# Thread Auto UI/UX 설계 명세

상태: 사용자 요청에 따라 화면·동작 개선을 코드에 적용. 검증 결과는 `UIUX_APPLIED_2026-09-08.md`에 기록.

기준: `output/pdf/Thread_Auto_UIUX_상세검토_2026-09-08.pdf`

사용자 요청: “개발 다 바꾸라고 개선 하라고 적용하라고 화면하고 모두다”

이 문서는 설계 기준이다. 실제 반영 내용과 검증 범위는 적용 기록을 따른다. 실제 계정 게시·결제와 배포 설치 파일 검증은 로컬 UI 회귀 검증에 포함되지 않는다.

## 1. 설계 원칙

- 기존 잉크·아이보리·청록의 시각적 정체성을 유지한다.
- 실행 대상 계정, 작업 수, 적용 범위를 실행 전에 명확히 표시한다.
- 과거 확인 기록과 현재 확인 상태, 누락 정보와 조회 실패를 구별한다.
- 작은 창에서도 상품 식별 정보와 핵심 실행 버튼에 접근할 수 있게 한다.
- 문구를 실제 기능에 맞춘다. 존재하지 않는 미리보기·문안 선택·전체 계정 배포를 약속하지 않는다.
- 원본 제휴 URL, 계정별 대기열, 복구 상태, 기존 사용자 수정 내용을 보존한다.
- 보고서 22쪽의 추가 편의 기능은 아래 기본 개선과 분리해 후속 설계한다.

## 2. 정보 구조와 화면 책임

| 화면 | 책임 | 주요 동작 |
|---|---|---|
| 운영 홈 | 집계 범위가 명시된 결과, 사용 가능한 계정, 다음 할 일 | 새 자동화, 확인 필요한 계정 열기 |
| 자동화 | 선택 계정의 입력·검증·대기열·진행·복구 | 실행 검토, 추가, 안전 중지, 오류 해결 |
| 작업 기록 | 결과별 검색·상세·원 계정 재시도 | 상세 보기, 상품 링크 열기, CSV |
| Threads 계정 | 계정 연결·검증·계정별 간격 관리 | 연결 확인, 재연결, 삭제 |
| 설정 | 공통 AI·문안·미디어·앱 설정 | 변경 저장·취소, 계정/결제 관리 바로가기 |
| 구독·지원 | 이용권과 검증된 결제 정보 | 결제 관리, 조회 재시도, 지원 문의 |

계정·구독의 편집 진입점은 전용 화면에 모은다. 설정에 남는 연결은 동일 편집 화면으로 이동하는 바로가기이며 별도 값을 갖지 않는다.

## 3. 확정 기능 설계

### F01. 원 계정 재시도 / P1

- 이력의 표시명과 별도로 `account_id`, 작업 식별자, 원본 URL을 유지한다.
- 다른 계정에서 재시도하면 원 계정을 명시하고 해당 계정의 초안으로 이동한다.
- 현재 계정의 초안을 먼저 보존한다. 원 계정이 없거나 사용 불가하면 URL을 다른 계정에 자동 추가하지 않는다.
- 재시도 버튼의 반복 클릭으로 동일 항목이 중복 추가되지 않게 한다.
- 완료 기준: A 계정 실패 + B 계정 선택 상태에서 B로 잘못 실행할 수 없어야 한다.

### F02. 실행 범위와 시작 검토 / P1

- 기존 전체 실행 기능의 이름을 `모든 계정의 저장된 대기열 실행`으로 정한다.
- 좁은 버튼에는 `전체 대기열 실행`을 쓰고 설명에 전체 동작명을 제공한다.
- 입력 링크를 여러 계정에 복제하는 기능은 기존 전체 실행과 별개다.
- 실행 검토에는 대상 표시명과 @사용자명, 계정별 작업 수, 신규/제외 수, 업로드 간격을 표시한다.
- 실제 게시를 시작한다는 사실과 취소 버튼을 분명히 보여준다.
- 이용량은 서버 정책에 근거해 표시하며 미확인 비용·횟수를 추정값처럼 확정하지 않는다.

### F03. 계정 상태 / P1

- `미확인`, `확인 중`, `최근 확인됨`, `확인 오래됨`, `재로그인 필요`를 구분한다.
- 마지막 확인 성공 시각만으로 현재 `정상`을 단정하지 않는다.
- 최근 실패는 이전 성공보다 우선한다. 성공한 사용자명과 기대 사용자명이 일치해야 한다.
- 오래됨 판단의 시간 기준은 명시적 상수로 관리하고 설정·테스트에서 같은 값을 사용한다.
- 게시 직전 계정 확인은 화면 상태와 별개로 유지한다.

### F04. 구독 정보 / P1

- 무료, 일회결제, 정기결제, 조회 중, 조회 실패를 구분한다.
- 서버에서 검증한 만료일과 다음 결제일은 서로 다른 필드로 취급한다.
- 일회결제에는 `만료일`, 정기결제에는 `다음 결제일`을 사용한다.
- 실제 응답에 없는 날짜·결제수단을 생성하지 않는다. `서버에서 제공되지 않음`과 확인 경로를 표시한다.
- 현재 이용권과 결제 관리 버튼을 비교 요금제보다 먼저 배치한다.

### F05. 작은 창 작업 영역 / P1

- 기준 창: 760×560, 900×620, 1360×900 DIP.
- 높이가 짧은 창은 진행 단계를 `2/4 콘텐츠 생성` 같은 한 줄로 압축한다.
- 제목·진행·계정 영역은 약 120~132 DIP, 하단 실행 영역은 64 DIP를 목표로 한다.
- 760×560에서 작업 영역 280~300 DIP 확보를 목표로 실제 렌더링으로 조정한다.
- 실행 중에는 상태를 먼저 보여주되 상세 설명을 접어 대기열 식별 정보를 확보한다.

### F06. 좁은 표 / P1

- 상품명과 URL을 동시에 숨기지 않는다.
- 좁은 화면 행: 상품명 또는 URL 요약 / 채널·상태의 두 줄.
- 원본 URL은 행 상세에서 전체 확인·복사할 수 있다.
- 행 클릭과 Enter는 같은 상세 동작으로 연결한다.
- 긴 상품명, 상품명 미수집, 같은 채널 10건을 검증한다.

### F07. 상태 대비 / P1

- 배경·장식 팔레트를 유지하고 상태 텍스트에 별도 진한 색상 토큰을 둔다.
- 흰 배경의 경고·오류·성공 일반 텍스트는 4.5:1 이상을 목표로 한다.
- 어두운 패널에는 밝은 역상 상태 텍스트를 사용한다.
- 색상만으로 상태를 전달하지 않고 의미 있는 텍스트·아이콘을 병행한다.
- 4.48:1 같은 값은 반올림해 통과시키지 않는다. 비활성 요소는 별도로 평가한다.

### F08. 타이포그래피 / P2

- 본문 Regular 14~15 DIP, 설명 13 DIP, 버튼/라벨 Medium 14 DIP.
- 섹션 제목 17~18 DIP, 페이지 제목 22~24 DIP, 주요 지표 28~32 DIP.
- 본문 줄높이 1.45~1.6, 폼의 설명 폭은 제한한다.
- Pretendard Regular·Medium을 정식 배포 파일과 라이선스를 확인해 번들링한다.
- URL·로그 외에는 고정폭 글꼴을 사용하지 않는다.
- 실제 Windows 설치 환경에서 선택된 글꼴·굵기와 대체 글꼴을 검증한다.

### F09. 탐색 메뉴 / P2

- 짧은 한글 메뉴명은 `홈`, `자동화`, `기록`, `계정`, `설정`, `구독`으로 통일한다.
- 한 글자 약어나 영문자를 아이콘처럼 사용하는 방식을 일관된 벡터 아이콘으로 대체한다.
- 작은 메뉴에서도 뜻이 보이는 짧은 한글 라벨을 제공한다.
- 현재 위치, Alt 단축키, 툴팁, 접근성 이름을 유지한다.
- 도움말은 전체 사용법과 현재 화면 도움말을 구분한다.

### F10. 운영 홈 집계 / P2

- 마지막 실행 결과를 표시하면 `이번 실행`이라고 명명한다.
- `오늘 전체 계정` 결과는 날짜와 계정 범위를 고정해 영구 이력에서 집계한다.
- 0, 아직 집계되지 않음, 데이터 조회 실패를 구별한다.
- 계정 수는 연결 수와 확인된 사용 가능 수를 구별한다.
- 재시작 후에도 동일 기간·동일 이력이면 같은 집계가 나와야 한다.

### F11. 작업 기록 상세 / P2

- 원본 상품 URL을 여는 버튼은 `상품 링크 열기`로 명명한다.
- Threads 게시물 URL이 실제로 저장된 경우에만 `Threads 게시물 보기`를 제공한다.
- 상세에는 계정, 원본 URL, 실행 시각, 결과, 수집된 실패 사유를 표시한다.
- 없는 실패 사유·소요 시간을 만들어내지 않는다.
- 작은 화면의 집계는 한 줄로 압축하고 검색 결과를 우선한다.

### F12. 설정 적용 범위 / P1

- 간격은 `현재 계정`, AI·문안·미디어·앱 옵션은 `공통`으로 명시한다.
- 현재 편집 중인 @계정을 폼 가까이에 표시한다.
- 선택 계정만 바꾸는 저장에 `모든 계정에 적용`이라는 안내를 사용하지 않는다.
- 전체 적용을 제공할 경우 대상 계정과 변경 전후 값을 검토하는 별도 동작으로 구현한다.
- A 저장 후 B 값 유지, 전체 적용 시에만 모두 변경되는 것을 확인한다.

### F13. 설정 밀도와 경로 / P2

- 폼 최대 폭은 680~800 DIP로 제한하고 설명을 필드 가까이에 둔다.
- 계정·결제의 실제 편집 화면을 단일화한다.
- 저장 후 적용 대상과 저장 결과를 알려준다.
- 미변경·저장 중·저장 성공·저장 실패를 구별하고 실패 시 값 복원 흐름을 유지한다.

### F14. 오류 복구 / P2

- 세션 만료: 원 계정의 `다시 연결` 동작.
- 오프라인: `연결 복구 시 자동 재개` 표시와 안전 중지.
- 게시 결과 불확실: `게시 여부 확인` 동작. 일반 실패 재시도와 분리.
- 완료: 성공·실패 수를 우선 표시하고 실패 항목 검토로 이동.
- 문제 해결 후에도 원 작업·원 계정·진행 위치를 유지한다.

### F15. 로그인·가입 / P2

- 비밀번호 보기/숨기기와 Caps Lock 안내를 제공한다.
- 가입 다음/이전 버튼을 스크롤 밖에 두고 오류 필드에 초점을 이동한다.
- 아이디 수정 시 이전 중복 확인을 무효화한다.
- 로그인 정보 저장과 자동 로그인의 차이를 설명한다.
- 420×560에서 키보드만으로 각 단계를 완료할 수 있게 한다.

### F16. 온보딩 / P2

- 테스트 링크는 `링크 형식 검사 · 실제 게시 없음`으로 범위를 표시한다.
- 이미 완료한 준비 단계는 상태를 이어받는다.
- 연결/설정 작업 후 원래 단계로 복귀하고 다음 미완료 항목을 강조한다.
- 나중에 설정은 유지하며 운영 홈에 남은 준비 항목을 표시한다.

### F17. 업데이트 / P2

- 상태 변경 시 이전 용량·진행률·변경 내용을 초기화한다.
- 최신 버전 화면은 버전과 확인 결과를 중심으로 간소화한다.
- 다운로드 중 닫기의 의미를 명확히 표시한다.
- 실제 설치·재시작·서명 검증은 설치본에서 확인한다.

### F18. 웹과 앱의 약속 / P1

- 현재 자동 생성·게시 흐름을 유지하는 기본 개선에서는 웹 설명을 실제 동작에 맞춘다.
- 생성된 네 문안을 비교·선택하는 UI가 없는 동안 선택할 수 있다고 안내하지 않는다.
- 4안 비교·수정·선택 화면을 추가하려면 게시 데이터와 미리보기의 동일성을 별도 설계한다.
- 운영 웹 배포는 로컬 구현·검증과 별도 단계다.

## 4. 구현 순서

1. 실행 대상·표시 정확성: F01, F02, F03, F04, F12, F18.
2. 작은 창·글자·탐색: F05, F06, F07, F08, F09.
3. 운영·복구: F10, F11, F13, F14.
4. 첫 사용·설치: F15, F16, F17.

## 5. 완료 판정

- 변경 전 기존 미커밋 작업을 보존하고 메서드 단위로 수정한다.
- 동작 변경은 원 계정 재시도, 전체 실행, 날짜 누락, 설정 범위를 우선 테스트한다.
- 주요 6화면을 3개 창 크기에서 렌더링하고 한글·표·포커스·고정 버튼을 검사한다.
- Qt 배율 100/125/150/175/200%와 실제 Windows 배율 변경을 구분해 검사한다.
- 필수 컴파일과 `tools/sanity_check.py`를 실행한다.
- 실제 게시·결제·설치는 가상 UI 검증만으로 성공했다고 보고하지 않는다.
- 프로그램 재실행 시 확인 가능한 상태로 열어두고, 실행한 버전과 미검증 경계를 보고한다.

## 6. 이번 실행 상태

- 정상 진입점 `login_main.py`를 `pythonw.exe`로 실행했다.
- 로그인 창이 표시되고 응답하는 것을 확인했다.
- 프로그램 열기만으로 실제 게시·결제를 시작하지 않았다.
- 이 설계 확정 작업에서는 제품 소스를 변경하지 않았다.
